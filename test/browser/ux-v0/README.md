# SocriaUX v0 — browser checks

Playwright checks for `/ux-v0`. They drive the real app in Chromium, with the model and the image libraries **scripted** (their routes are stubbed in the browser), so they verify how the product behaves, not how well the real model reasons. The exception is `moodboard-live.mjs`, which searches the real Openverse. The real-model run is decision D9 in `docs/SOCRIAUX-V0.md`.

They are not part of `npm test`, because they need a running app and a browser. The runner only collects `test/*.test.mjs`.

## Running them

1. Start the app with the v0 switch on. It is on in development by default:

   ```bash
   npx next dev -p 3100
   ```

2. `sections.mjs`, `gallery.mjs` and `benchmark.mjs` render through the modules under test, so build those first. `npm test` builds them too:

   ```bash
   node -e "import('./test/helpers/build.mjs').then((m) => m.buildAll())"
   ```

3. Run a check. Each prints `PASS` and `FAIL` lines and a summary:

   ```bash
   node test/browser/ux-v0/checklist.mjs
   ```

| Variable | Meaning | Default |
|---|---|---|
| `UXV0_BASE` | the running app | `http://localhost:3100` |
| `UXV0_OUT` | where screenshots and captures go | a folder in the system temp directory |
| `PLAYWRIGHT_MODULE` | a Playwright to load instead of the one `require('playwright')` finds | — |

## What each one covers

| Script | Covers |
|---|---|
| `workflow-a-create.mjs` | Workflow A end to end: intent, question, moodboard (keep, remove, replace), answer, brief, art direction (three drawn as specimens, asked again with the designer's own words, one changed and so kept, then taken), generate in that direction, the checks at desktop and phone widths, change, undo, critique, versions, cost. |
| `workflow-b-critique.mjs` | Workflow B end to end. An HTML import in its sandbox: its script, `parent`, storage and the network are all unreachable. Element and area selection, a card and its follow-up, a PNG crop with its one-time thumbnail, reload persistence. |
| `checklist.mjs` | Refused files, SVG and JPG imports, zoom keys, stepping through the page with what is announced, the missing-files line, workspace widths, the home list and its inline delete, answer and brief editing, refinement moving the board, versions, drops, storage full, a failed call kept with *Try again*. |
| `acceptance.mjs` | Every kind of element selectable. The highlight through zoom and panning. A card's area returning its heading, text and button. Viewport switches keeping the selection. Forged and malformed messages ignored. axe on the workspace shell. A 4000 px screenshot and a 16 px icon. Zoom about the pointer. Areas in image pixels at any zoom. Crops on 1× and 2× screens. Sign-in at the first model call. Discovery at 390 px. A provider failure on the board. Brief edits through a reload. An area on a generated design. An exact undo. |
| `moodboard-live.mjs` | The moodboard against the **real** Openverse; it needs network access to `api.openverse.org`, and uses `HTTPS_PROXY` when one is set. Long model queries must still fill every group with relevant, loaded, credited images. Also covered: *More images*, *More like these*, the board's own search, *Replace*, and no image shown twice. |
| `sections.mjs` | Every section kind and variant, across the five classic styles and all twelve visual languages, three palettes (a light accent and a dark ground among them), with each section on a different ground (base, alternate, accent, second ink, inverted). Each must render cleanly, keep text at 4.5:1 (over images, at the worst case), give 44 px targets at 390 px, and never scroll sideways. |
| `gallery.mjs` | Every gallery count from 1 to 8, grid and mosaic, at three widths: no image-sized hole and no overflow. |
| `benchmark.mjs` | The art-direction benchmark (`docs/SOCRIAUX-ART-DIRECTION.md`). Nine briefs (`benchmark-briefs.mjs`, Socria's own landing page and launch among them) drawn by the previous renderer and in the engine's three directions; each measured at 1280 and 390 px, evaluated and revised in at most two rounds. Reports quality, distinctiveness, diversity, fidelity, latency and cost, and writes screenshots, `results.json` and `contact-sheet.png`. Real photographs come from Openverse when the network allows (`BENCH=socria,lumen` runs a subset). |

| `dogfood.mjs` | Dogfooding (`docs/SOCRIAUX-CREATIVE-WORKSPACE.md`). Six kinds of project (Socria's promotional site and product announcement, a research lab, an experimental portfolio, a finance interface, a dance company) asked four ways each: a minimal brief, a detailed specification with locks and rules, an extensive moodboard with notes, sampled colours and a moving reference, and experimental notes. Each case is proposed by the direction engine, laid out, drawn and photographed at 1280 and 390 px (and mid-arrival for motion), then measured: fidelity to direction, locks and rules; sideways scroll on a phone, static and playing; and any headline word broken across two lines. Writes `dogfood.json` and `df-*.png`. With `HTTPS_PROXY` set it loads the real typefaces from Google Fonts; `UXV0_FONTS=stub` uses system fallbacks. |

| `sol-eval.mjs` | The creative-quality test of GPT-6.1 Sol (`docs/SOCRIAUX-SOL.md`), against the **real** OpenAI API: the six dogfood projects through questions, brief, moodboard direction, art direction, generation (drawn, measured and fixed as the workspace does), a targeted refinement and a critique, on Sol at high and medium effort (and GPT-6 Luna with `--baseline`). It spends money: nothing is sent without `--yes`, it prints the worst case first and stops past `--max-usd`. `--dry-run` checks the plumbing against the strict fake, free. Writes `sol-eval.json` and `sol-eval-*.png`. |
| `dogfood-projects.mjs` | The six projects, shared by `dogfood.mjs` and `sol-eval.mjs`. |
| `layout-bench.mjs` | Layouts the designer decides (`docs/SOCRIAUX-LAYOUT.md`), offline and with no model call. It checks that one project draws the same directions every time and another project draws other ones. It counts distinct booking structures across 20 briefs, each its own project, and the same brief across 20 projects. It checks that decisions hold in every direction (what leads, centred, uneven, no pictures), and that no centred opening or rounded-cards-everywhere appears where nothing was decided. Every booking study is drawn at 1280 and 390 px, audited, and put through the booking's own self-test. It needs no app server; build the modules first. Writes `layout-bench.json` and `layout-bench.md`. |
| `craft-bench.mjs` | The four methods against the generated look (`docs/SOCRIAUX-CRAFT.md`), offline and with no model call. Across 720 directions in every language, no generated look appears that nobody asked for. Every direction states a whole plan with a move it can draw, and every study makes that one move, visibly, and no other loud one. A sample design system with faces SocriaUX cannot serve is kept by every direction and passes the check against it. Openings composed from layout pieces are counted. The studies are drawn at 1280 and 390 px and checked for sideways scroll, contrast, generated looks on the rendered page, and the composed opening being the page's h1. It needs no app server; build the modules first. Writes `craft-bench.json` and `craft-bench.md`. |
| `dna-bench.mjs` | The Creative DNA & Originality Engine (`docs/SOCRIAUX-CREATIVE-DNA.md`) on five very different briefs: luxury fashion, a scientific dashboard, an architecture studio, an experimental portfolio and a booking app. It runs offline, with no model call. For each brief it derives the DNA. It draws the same brief from a restrained and an expressive DNA, reads both studies back, renders them in Chromium and compares the first screens and the spec's structure. It checks that the three directions differ in at least three of six aspects and that no pair differs only in colour. Locks must hold when SocriaUX is asked again. A change against a locked dimension must be caught, and a drifted page moved back. Fixture references are measured from their pixels through a browser canvas and must move the DNA, keeping only numbers and phrases. The Originality Audit reads every study; a deliberately generic page must be caught and fixed in one pass. The booking's self-test must pass in place, and the dashboard must have its figures, chart and table. It also times each step and measures what the DNA adds to a prompt. It needs no app server; build the modules first. Writes `dna-bench.json`, `dna-bench.md` and `dna-*.png`. |
| `production-bench.mjs` | The Advanced Creative Production Engine (`docs/SOCRIAUX-PRODUCTION-ENGINE.md`) on six projects: luxury fashion editorial, experimental architecture studio, high-end creative agency, motion-rich artist portfolio, immersive 3D product, scientific research interface. Offline, no model call. Each takes the engine's first direction and its study further with the canvas tools (made pictures, interactive parts, 3D, motion, width rules), every step a patch checked to touch only what it names (in the spec and in the drawn page). The page is measured at 1440, 834 and 390 px with the bounded repair; the interactive, 3D (pixels read back) and motion (the story played through) self-tests run in Chromium; reduced motion, script errors, weight, load time and frames while scrolling are checked; the same study with motion still is the baseline. It needs no app server; build the modules first. Writes `production-bench.json`, `production-bench.md`, `prod-*.png`, each project's spec and `prod-contact-sheet.png`. |
| `ceiling-bench.mjs` | The creative ceiling (`docs/SOCRIAUX-CREATIVE-CEILING.md`): seven ambitious briefs through this engine and an earlier commit's (`UXV0_BASE_COMMIT`, or a bundle at `UXV0_BASELINE`), the same conventional model answer for both, no model called. It measures how much of what the words asked is in the design, the opening's arrangement, quality and originality, overflow and collisions at three widths, every interactive part, the menu, the 3D object, five targeted changes, and the prompt's size. |
| `originality-bench.mjs` | Visual originality (`docs/SOCRIAUX-VISUAL-ORIGINALITY.md`): six identities and a plain page through this engine and an earlier commit's (default 3df371a; `UXV0_NO_BASELINE=1` to skip it). It measures structural similarity across the six, spatial logics, shape vocabularies and repetition, pictures integrated, unjustified habits, the strategy held, overflow, collisions and contrast at three widths, links that go somewhere, and that a plain page stays plain. Writes a before/now/phone contact sheet. |
| `explore-qa.mjs` | Exploring a part's composition in the real app (`next start`): a website project written into the browser's own store, then explore, set aside (remembered by the project), combine, nudge, use (held), release, the canvas's links, no sideways scroll at three widths, no script error. |
| `perf-bench.mjs` | Speed, cost and reliability (`docs/SOCRIAUX-PERFORMANCE.md`), through the real route handlers, with no provider called. Scenarios A–G (Starting Fresh, questions, art direction, the first design, six small refinements, a complex one, and a workshop of designers at once, each double-pressing an action), plus a stalled provider, a cancelled generation, a broken answer and the provider's rate limit. The model (`test/helpers/fake-openai-perf.mjs`) answers each stage after its median time from the live run of 18 November 2026, scaled by `PERF_SCALE`; every database query costs `PERF_DB_MS`. It counts requests, model calls, database round trips, SocriaUX's own overhead, prompt sizes and the prefix two projects share (what a provider can cache). `PERF_ROOT` measures another checkout under the same conditions, for a before-and-after. Writes `perf-bench.json` and `perf-bench.md`. |

The photographs in `fx/` are small stand-ins. `kinds.html` and `existing-design.html` are the pages the critique checks import.
